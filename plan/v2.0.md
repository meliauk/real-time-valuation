# 并发架构与取数口径方案 · v2.0

> 状态：已落地。
> 承接 v1.0 并发架构（5 板块 / 基金 3 Worker），本轮 v2.0 聚焦**取数口径正确性**与**已确认状态稳定性**。

---

## 一、v2.0 要解决什么

v1.0 把并发隔离做对了（腾讯 fetch 主源进 Worker、东财 JSONP 退主线程、Yahoo 单代理限流），但上线后暴露四个"取到了数据却算错/丢失"的问题：

1. **美股盘前涨跌对不上东财**：基准取了 `previousClose`，与东财用的"上一交易日正式收盘价"(`regularMarketPrice`) 不同，幅度偏差、甚至方向相反（NVDA 盘前本 app +1.92%、东财 −2.02%）。
2. **盘前未开的空窗期美股实时全 `--`**：工作日北京 08:00–16:00 美股盘前没开，Yahoo 只返回上一交易日 bar，被"当日 bar 过滤"丢弃 → 算不出 → 实时列空白。
3. **实时取数失败后迟迟不重试**：`tickOnce` 的 `hadMissing` 只判 close 模式，realtime 即便 40/98 失败也判 `hadMissing=false` → loop 走 60s 心跳而非 3s 重试 → 失败股迟迟补不齐。
4. **已确认的"已更新"状态会消失**：fundgz/lsjz 刷新偶发失败时，已确认基金被估算值覆盖或被清理块回退为估算 → "已更新"徽章消失、今日涨跌归零，但累计收益仍正常（状态与数据脱节）。

**v2.0 原则**：取到的数据要算对口径；已确认的状态是最高优先级，绝不被刷新失败回退。

## 二、v1.0 并发架构（不变，本轮基础）

### 2.1 板块 = Worker（+ 基金板块内部 3 Worker）

```
GitHub Pages（纯静态，零后端）
│
├─ 主线程（UI + 调度中枢）
│   ├─ UI 渲染、Worker 生命周期、请求分发、结果聚合、Pinia 写入
│   └─ 少量主线程兜底取数（东财 JSONP 兜底 / fundgz 估值）
│
├─ 基金板块（3 Worker）
│   ├─ Worker ①  fund-em-close    收盘线（腾讯 fetch 主源）
│   ├─ Worker ②  fund-em-realtime 实时线（腾讯 fetch 主源）
│   └─ Worker ③  fund-yahoo       Yahoo-综合线（fetch+代理，美股盘中走腾讯）
│
├─ Worker ④  index       指数板块
├─ Worker ⑤  stock       股票板块
├─ Worker ⑥  news        资讯板块
└─ Worker ⑦  reserved    预留板块（空壳）
```

### 2.2 各数据源在 Worker 内的可用性

| 数据源 | Worker 内可用方式 | 在架构中的角色 |
|--------|------------------|---------------|
| 东财 push2/push2his（JSONP） | ❌ Worker 不可用 | 主线程兜底（仅 Worker 失败时补） |
| 腾讯 fqkline 日K / qt.gtimg 报价（fetch, CORS 放行） | ✅ Worker 内 fetch | **东财线主源**（Worker 内） |
| Yahoo chart/search（fetch + 公共代理） | ✅ Worker 内 fetch | Yahoo 线主源 |
| 海外 RSS（fetch + 代理） | ✅ Worker 内 fetch | 资讯线海外源 |
| 天天基金 fundgz（JSONP） | ❌ Worker 不可用 | 基金估值主线程取 |

> importScripts 路线已废弃（Worker 内跨域被安全策略拦截），东财 JSONP 退居主线程兜底；东财线主体走腾讯 fetch 进 Worker。

### 2.3 实时取数分市场分时段选源

实时涨跌按市场 + 美股时段选源：

| 场景 | 数据源 | 说明 |
|---|---|---|
| A股、港股 实时 | 腾讯 `qt.gtimg` | em-realtime 线，现价 vs 昨收 |
| 美股 **盘中**（美东 09:30-16:00）| 腾讯 `qt.gtimg`(`usAAPL`) | Yahoo 线 Worker③ 内判 REGULAR 时段走腾讯，绕开 Yahoo 2m 大请求代理易失败 |
| 美股 **盘前/盘后** | Yahoo chart | 需计算（见 v2.0 §三.1） |
| 其他海外（日韩台欧）| Yahoo chart | 直取 `regularMarketChangePercent`（`calcRealtimeSimple`） |

### 2.4 启动时序（不变）

loop 必须在持仓预取**之后**启动，否则首轮 collectMissingStocks 因持仓缓存未就绪收集到 0 股 → 误判全齐 → 转 60s 心跳 → 首屏空白。启动流程见 v1.0。

## 三、v2.0 取数口径修复

### 3.1 美股实时涨跌基准修正（`yahoo-realtime-calc.ts`）

**实测结论**（通过 allorigins 代理探测 Yahoo chart，3 轮恒定）：
- Yahoo chart `interval=2m&range=1d&includePrePost=true` **不返回** `marketState`、`preMarketPrice`、`preMarketChangePercent`、`postMarketPrice`、`regularMarketChangePercent` → 原第一/二层（用现成字段）恒 miss，实际走第三层 bar 回退自算。
- `regularMarketPrice` 与 `previousClose` 是**两个不同的"昨收"**（探测：TSM 434.11 vs 436.96；NVDA 210.96 vs 202.78，差 4%）。反推东财盘前基准 = `regularMarketPrice`，本 app 原用 `previousClose` → NVDA 方向反。

**分时段基准（对齐东财口径）**：

| 时段 | 基准字段 | 说明 |
|---|---|---|
| **PRE 盘前** | `regularMarketPrice` | 上一交易日正式收盘价（PRE 时段定格）。**改自 previousClose** |
| **REGULAR 盘中** | `previousClose` | 昨收（此时 regularMarketPrice 是当日实时价，不能做基准） |
| **POST 盘后** | `regularMarketPrice` | 当日正式收盘价 |
| **OFF 盘外** | `regularMarketPrice` vs `previousClose` | 上一交易日当日涨跌，兜底显值 |

四层兜底（`calcRealtimeChangeRateByMarket`）：
1. marketState 路由取现成 ChangePercent（实测恒 miss，留作防御）
2. 对应时段 Price vs 基准自算（PRE 基准改 regularMarketPrice）
3. bar 回退：当日 bar 优先；**当日无 bar（盘前未开的交易日）退取 lastClosedDay 的盘后 bar 作定格值**，基准 regularMarketPrice → 显上一交易日盘后数据（v2.0 新增退取逻辑）
4. meta 兜底：`regularMarketPrice vs previousClose`，date=lastClosedDay（连盘后 bar 都没有时）

> v1.0 待验证的"美股盘前/后数值偏差（+4.86% vs +2.52%）"即此问题，v2.0 修复。

### 3.2 空窗期显示前值（产品语义）

美股无"盘外"概念——盘前未开(北京 08:00–16:00)时，实时列显示**上一交易日盘后定格值**，而非 `--`。由 §3.1 的 Layer 3 退取 lastClosedDay 盘后 bar 实现。

| 场景 | 实时列显示 |
|---|---|
| 工作日盘前未开(北京08:00–16:00) | 上一交易日**盘后**涨跌（退取 lastClosedDay POST bar） |
| 周末休市 | 上周五盘后涨跌（currentTradingDay=周五，周五 POST bar 直命中） |
| 盘前开盘(16:00+) | 当日盘前实时（基准 regularMarketPrice） |
| 盘中(21:30+) | 当日盘中实时（走腾讯） |

> 实时列(盘后)与收盘列(当日收盘涨跌)是两个不同口径，并存显示。

## 四、v2.0 并发与重试调整

### 4.1 并发适度调大（`constants.ts` + `yahoo-worker.ts`）

实测取数失败主因非并发（而是代理限流 + 偶发超时），适度调大提升取数速度：

| 配置 | v1.0 | v2.0 | 位置 |
|---|---|---|---|
| `YAHOO_CONFIG.SLOT_CAP_PER_SOURCE` | 1 | 2 | constants.ts |
| `YAHOO_CONFIG.SYMBOL_CONCURRENCY` | 2 | 3 | constants.ts |
| `FUND_LOOP_CONFIG.KLINE_SERVICE_BATCH` | 12 | 20 | constants.ts |
| `FUND_LOOP_CONFIG.KLINE_WORKER_CONCURRENCY` | 3 | 6 | constants.ts |
| `FUND_LOOP_CONFIG.KLINE_BATCH` | 2 | 4 | constants.ts |
| `FUND_LOOP_CONFIG.REALTIME_BATCH` | 50 | 80 | constants.ts |
| Yahoo worker `BATCH_CONCURRENCY` | 3 | 5 | yahoo-worker.ts |

> Yahoo 路调幅保守（代理对并发敏感），东财/腾讯路（直连）调幅较大。

### 4.2 realtime 重试间隔修复（`yahoo-service.ts`）

**原 bug**：`tickOnce` 的 `hadMissing` 仅判 close 模式，realtime 即便失败也判 false → loop 走 60s 心跳而非 3s 重试。

**修复**：补 realtime 缺失判定：
```js
if (mode === 'realtime' && fetched.size < rtEntries.length) hadMissing = true
```
realtime 有失败股 → `hadMissing=true` → loop 走 3s 短重试（`RETRY_INTERVAL`），失败股被密集重试。

### 4.3 loop 节奏（两路）

| 路 | 有缺失 | 全齐 |
|---|---|---|
| Yahoo 路 | 3s 重试 | 60s 心跳 |
| 东财 realtime 路 | 3s 刷新（至少一市场盘中）| 60s 心跳（都收盘/休市）|

## 五、v2.0 已确认状态保护（最高优先级）

### 5.1 问题

"已更新"徽章判定（`use-fund-data.ts:69`）：`isUpdated = !isEstimated || v?.jzrq === today`。已确认基金靠 `!isEstimated` 显示。T+2 确认净值滞后 2 天，`jzrq` 恒为上一交易日（永远 `!== today`），只能靠 `!isEstimated`。

刷新偶发失败时，`isEstimated` 被翻回 `true` → 徽章消失、今日涨跌归零，但累计收益正常（`holdingStore` 的 `yesterdayAmount` 推进独立于 `isEstimated`，状态与数据脱节）。

### 5.2 两条回归路径与修复（`fund-store.ts`）

**路径 A — 清理块误清已确认基金**（原 622-634）
刷新后遍历不在 `refreshedCodes`（fundgz+lsjz 都失败）的基金，若 `gztime/jzrq !== today` 就置 `isEstimated=true`。T+2 确认值日期恒为上一交易日 → 被误清。
**修复**：加守卫 `v.isEstimated !== false`，已确认基金一律跳过清理。

**路径 B — 估算值覆盖已确认基金**（原 553-562，更常见）
fundgz 成功但 lsjz 失败时，原"跨日允许覆盖"例外放行用估算对象替换 → `isEstimated=true`。
**修复**：已确认基金遇到新估算值时**继承确认字段**（`isEstimated=false`/`confirmedGszzl`/`jzrq`/确认 `gszzl`/`gz`），保留估算带来的盘中 `gz`/`gztime` 供走势图重算（不 `continue`，避免跳过走势图更新）。

### 5.3 原则

- 已确认状态只能由 lsjz 成功（`fund-valuation-merge.ts` 设 `isEstimated=false`）正常推进。
- 刷新失败绝不回退已确认状态，不论 T+1 还是 T+2。
- 未确认（估算）基金刷新失败仍按原逻辑清理过期数据（守卫 `!== false` 放行）。

## 六、设计决策（v1.0 沿用 + v2.0 补充）

v1.0 决策 1-12 仍有效（A股交易日历独立、回调注入解耦、calc 纯计算、持仓涨跌独立于确认状态、收盘列锚美股、Yahoo Worker 边界、批次限流、脏 bar 过滤、failed 占位、搜索透传、录入即冻结、连接竞争治理）。v2.0 补充：

13. **美股分时段基准**：盘前/盘后基准取 `regularMarketPrice`（上一交易日/当日正式收盘价），盘中取 `previousClose`（昨收）。Yahoo `previousClose` 与 `regularMarketPrice` 不同口径，盘前用错会方向反。
14. **空窗期显前值**：美股盘前未开时实时列显上一交易日盘后定格值（退取 lastClosedDay POST bar），不显 `--`；周末显上周五盘后。实时列(盘后)与收盘列(当日收盘)并存。
15. **已确认最高优**：`isEstimated=false` 一旦确立，刷新失败不回退（清理块跳过 + 估算覆盖时继承确认字段）。T+1/T+2 通用。
16. **realtime 缺失触发短重试**：close/realtime 任一有未取到的股 → `hadMissing=true` → 3s 重试，避免 realtime 失败被误判全齐走 60s 心跳。

## 七、待验证 / 已知局限

- **Yahoo 单代理（allorigins）**：海外实时、美股盘前盘后依赖它，代理挂时取数全空，靠 loop 接力重试 + 缓存临时展示兜底。美股盘中走腾讯不受影响。换稳定私有代理可解，暂未做。
- **美股盘中基准未实测**：§3.1 REGULAR 基准 `previousClose` 按代码意图保留，未在盘中时段实测验证（探测在盘前完成）。REGULAR 实际多走腾讯（用腾讯 prevClose），Yahoo 路仅 Tencent 未命中时兜底。
- **symbol 解析失败**：纯数字德股（ENRGR/RHMGR/312240 等）emCode 缺失、Search 命中率低，本轮未治。
